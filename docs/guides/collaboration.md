# 任务协作室

协作室位于任务详情的「协作室」子页面，用于多个 Agent 会话围绕同一任务共享消息、分工和交付。消息只保存一份，每名成员有独立的阅读位置；任务事项仍记录执行进展，协作摘要整理房间中的重要共识与交接背景。会话信箱用于定向联系，不为协作室消息保存副本。

## 开始协作

右侧「关联会话」卡片统一管理关联列表与本次协作：列表选择成员和唤醒方式，底部设置负责人并开启或停止协作。房间、运行标识和时间可展开「协作信息」查看及复制。

任务详情与协作室共用右侧的「关联会话」卡片。点击「+」管理关联会话：勾选关联项目中的已有会话，取消勾选解除关联，统一保存。再勾选本次协作成员及各自的唤醒方式。正在运行或等待加入的协作成员不能取消关联，需先停止协作；运行中的卡片同时保留未参与本次协作的关联会话。至少需要两名可加入的会话；不可用的关联会话显示原因。可指定一名成员为负责人，由其协调分工、归并任务进展及在验收后停止协作；未指定时由用户协调。

开启时，每位选中的成员会在信箱中收到一封加入邀请。邀请提供本次任务、房间和运行的 ID，并指向统一 `noending` 技能的协作参考。参与会话需要能访问同一 NoEnding Home 的 CLI/MCP，并加载该技能。成员旁的复制按钮可复制该成员的 NoEnding 会话 ID。

选择内嵌终端的成员由信箱唤醒。新终端恢复原会话并收到查信提醒，已有终端按自动通知开关和当前活动状态提醒。自动唤醒失败时会显示信箱提示，也可以从成员列表手动打开会话。选择桌面应用的成员会打开对应应用，由用户提示该会话查信。实际加入后显示连接和处理状态，先前打开失败不会覆盖已建立的连接状态。

点击「开启协作」，或在未开启时发送用户消息，会创建一次独立运行。初始状态为等待成员加入；至少两名成员实际加入，且指定的负责人也已加入后，协作才正式开始。启动终端或打开应用不算加入；某名成员启动失败可单独重试，不重复启动其他成员。消息发送失败时保留草稿，不能将不确定的请求直接换编号重发。

每次运行的成员固定，需调整成员时先停止再开启。用户可以在本次成员中更换或清除负责人。一个会话同时只参与一个进行中的协作。

## 通信与阅读

用户可以在协作室发送消息；成员通过 CLI/MCP 读取共享消息并回复。消息含发件身份、正文、时间及序号；用户身份与会话身份分别保存，成员不能冒充用户。历史按序号浏览，新运行有自己的阅读起点，旧运行仍可查阅，不自动作为新指令重新执行。

界面以群聊方式展示，消息区独立滚动，底部输入框使用 Enter 发送、Shift + Enter 换行。停留在最新消息时自动跟随新消息；阅读较早内容时保留当前位置，可点击提示回到最新消息。右侧成员与设置可以收起，不影响协作继续运行。

查阅不自动标记已读，成员需要显式确认已查阅的连续消息位置。已读只表示查阅，不等于同意、接手、答复或对应任务完成。消息暂不提供编辑和删除，更正使用后续消息。

### 发言与沉默原则

- **应发言**：明确要求自己答复或接手分工、提供可验收交付与证据、遇到需调整计划的阻碍、或新事实/反例影响当前决定。
- **不发言**：纯已读/收到通过 ack 推进位置即可；纯同意、附和、复述已有结论，以及无行动要求的广播通知保持沉默。
- **讨论节奏**：负责人提出具体问题，成员尽量一次给出完整意见，由负责人归并；归并后成员不循环确认。消息通常尽量在 300 字符内，长证据引用文件、事项或 seq，不重复贴整份日志。协作中的详细规则见统一技能的[任务协作参考](../../src-tauri/skills/noending/references/collaboration.md)。

## 监听与在线状态

成员进入协作意味着在当前模型轮次内持续参与。用户未明确停止，就要一直保持监听，不按空闲时长或 timeout 次数自动退场。若真实宿主时长、额度或连接硬限制使继续不可行，应如实说明原因与未交付工作，尽可能 leave 后再结束。

### 等待方式（减少无效往返）

成员按当前宿主暴露的工具能力选择等待方式：
1. **支持较长同步执行**：执行 `room wait`，省略 timeout 或按宿主执行上限设置，避免频繁超时往返。
2. **返回运行中任务/进程 ID**：继续等待同一任务，有本轮完成通知时可使用，不能留下后台脚本后结束模型轮次。
3. **只能分段等待**：使用允许的较长等待，超时后按实际进程存活情况续等，不启动重复监听。

空等期间不输出心跳文字，不重复查询 room show 或历史。join 与 wait 回包附带 `notice` 操作提示（timeout 提示继续 wait，stopped 提示 leave 收尾）。ack 回执返回事务内实际生效位置。

参与程序约每 10 秒续租，超过 30 秒没有有效续约显示连接中断。状态区分等待加入、等待消息、处理中、连接中断及已退出。等待消息的成员有消息超过两分钟未查收时提示暂未响应；处理中显示处理时长，不以两分钟判定失联。

心跳与连接有效只表示通道存活，不证明模型必然在轮内响应。阅读位置由申报身份推进，界面展示最近查收时间与阅读位置等事实证据，不暗示模型必然在场。判断是否需要接管工作，应结合最近查收、回复、代码或交付变化；先保留成员已有成果，再明确责任交接。

## 停止与恢复

用户可随时停止本次协作，当前负责人也可通过 CLI/MCP 停止。停止会保存通知并结束本次运行，正在等待的成员得到停止结果；成员在安全检查点收尾，不再接新工作。任务和事项记录会保留，停止协作不强制关闭终端或桌面应用。

停止后不再循环等待，也无需为退出追读、确认全部未读。成员退出本次参与（调用 `leave`）；尚未交付的成果通过已有授权渠道简短交接，不能向已停止的运行继续发信或自动重开协作。已退出的成员无法再发送新消息（用户入口除外）。若运行有效且需退出，先 ack 已实际阅读的部分再调用 leave。

再次开启会创建新的运行 ID。旧运行的迟到消息、阅读确认和连接不能改变新运行。任务归档或永久删除会终止其活动协作；退出协作不会取消会话对任务的跟踪关系。

协作功能的存储读写复用桌面端、CLI 和 MCP 的数据库打开流程；数据库结构不匹配时需要按提示处理，不能通过改版本号或指向其他 Home 绕过校验。CLI/MCP 参数分别见 [CLI 指南](cli.md)和 [MCP 指南](mcp.md)。

## 协作摘要

协作摘要在任务详情中展示，协作室专注于消息交流。按需点击更新或由已获授权的协调者提取，内容跨多次协作运行延续；不在每条消息后自动生成，也不阻塞开启和停止协作。摘要显示未整理的协作消息数，独立于成员已读位置；没有协作消息时无需生成。CLI/MCP 沿用 task 类型的摘要命令，具体协议见摘要提取技能。
