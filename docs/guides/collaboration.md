# 任务协作室

协作室位于任务详情的「协作室」子页面，用于多个 Agent 会话围绕同一任务共享消息、分工和交付。消息只保存一份，每名成员有独立的阅读位置；任务事项仍记录执行进展，摘要仍负责整理记忆。会话信箱用于定向联系，不为协作室消息保存副本。

## 开始协作

先将参与会话关联到任务，再进入协作室选择本次成员及各自的唤醒方式。至少需要两名可加入的会话；不可用的关联会话显示原因。可指定一名成员为负责人，由其协调分工、归并任务进展及在验收后停止协作；未指定时由用户协调。

内嵌终端方式使用会话原生恢复能力，并提供简短的加入提示；桌面应用方式打开对应应用，由用户将加入提示交给该会话。可选方式取决于会话所属 Agent 的实际能力，不是所有历史来源都支持终端或桌面启动。参与会话需要能访问同一 NoEnding Home 的 CLI/MCP，并加载已启用的统一 `noending` 技能。

已有内嵌终端会安全复用，不向未知草稿追加输入；此时请复制成员旁的加入提示发送给会话。所有成员均可复制提示，供未自动加入时使用。实际加入后显示连接和处理状态，先前打开失败不会覆盖已建立的连接状态。

点击「开启协作」，或在未开启时发送用户消息，会创建一次独立运行。初始状态为等待成员加入；至少两名成员实际加入，且指定的负责人也已加入后，协作才正式开始。启动终端或打开应用不算加入；某名成员启动失败可单独重试，不重复启动其他成员。消息发送失败时保留草稿，不能将不确定的请求直接换编号重发。

每次运行的成员固定，需调整成员时先停止再开启。用户可以在本次成员中更换或清除负责人。一个会话同时只参与一个进行中的协作。

## 通信与阅读

用户可以在协作室发送消息；成员通过 CLI/MCP 读取共享消息并回复。消息含发件身份、正文、时间及序号；用户身份与会话身份分别保存，成员不能冒充用户。历史按序号浏览，新运行有自己的阅读起点，旧运行仍可查阅，不自动作为新指令重新执行。

查阅不自动标记已读，成员需要显式确认已查阅的连续消息位置。已读只表示查阅，不等于对应任务完成。消息暂不提供编辑和删除，更正使用后续消息。

建议消息先写结论或具体请求，引用已有任务事项、提交或文件，避免重复贴整份任务进展和日志。负责人维护任务整体记录，成员报告本职成果及阻碍；无需回应时保持沉默，避免相互确认造成循环。协作中的详细规则见统一技能的[任务协作参考](../../src-tauri/skills/noending/references/collaboration.md)。

## 监听与在线状态

成员空闲或等待依赖时持续等待新消息；有工作时在检查点查阅。没有新消息时监听不返回周期性空通知。当前仅支持模型轮次内参与：外部 Agent 若结束轮次，新消息不会自动唤醒该宿主继续生成。

参与程序约每 10 秒续租，超过 30 秒没有有效续约显示连接中断。状态区分等待加入、正在监听、处理中、连接中断及已退出。正在监听的成员有消息超过两分钟未查收时提示暂未响应；处理中显示处理时长，不以两分钟判定失联。

心跳只表示参与通道存活，不证明模型正在响应。判断是否需要接管工作，应结合最近查收、回复、代码或交付变化；先保留成员已有成果，再明确责任交接。

## 停止与恢复

用户可随时停止本次协作，当前负责人也可通过 CLI/MCP 停止。停止会保存通知并结束本次运行，正在等待的成员得到停止结果；成员在安全检查点收尾，不再接新工作。停止不强制关闭终端或桌面应用，不自动完成任务事项或归档任务。

停止后不再循环等待，也无需为退出补读、确认全部未读。成员退出本次参与；尚未交付的成果通过已有授权渠道简短交接，不能向已停止的运行继续发信或自动重开协作。

再次开启会创建新的运行 ID。旧运行的迟到消息、阅读确认和连接不能改变新运行。任务归档或永久删除会终止其活动协作；退出协作不会取消会话对任务的跟踪关系。

协作功能的存储读写复用桌面端、CLI 和 MCP 的数据库打开流程；数据库结构不匹配时需要按提示处理，不能通过改版本号或指向其他 Home 绕过校验。CLI/MCP 参数分别见 [CLI 指南](cli.md)和 [MCP 指南](mcp.md)。
