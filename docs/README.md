## 开发约定

- 工程结构、开发与验证规则统一维护在仓库根目录的 [AGENTS.md](../AGENTS.md)。

## 临时开发材料（不提交）

`.tmp/docs/` 用于本机开发过程中的方案草稿、调查原稿、排查笔记、实测报告和专项实施记录，不作为当前功能或开发规范。

调查中确有长期复用价值的格式、接口和设计结论，应核实并整理后再写入正式文档，不直接提交整份采样过程或本机统计。一次性迁移工具及其说明完成使用后删除，不作为长期文档归档。

## 维护方式

- 判断是否提交，看其是否需要长期维护和复用；不因为文件是 Markdown 或位于文档目录就默认提交。
- 正式文档按用途放入 `docs/` 对应目录，在此索引登记并随实现更新。一个主题保留一个主要入口。
- 正式 `docs/` 正常受版本控制，不使用整个目录的忽略规则或单文件白名单；临时材料通过放入 `.tmp/docs/` 区分。
- 调查和历史材料标注日期或适用版本，不将旧方案中的“必须”当成当前规则。
- 临时日志、测试产物和原始样本同样放在 `.tmp/`，不放入正式文档目录。
- 移动文档时同步修正仓库链接及代码中的 `include_str!` 等引用。CLI 手册会作为内置助手的资源打包，源文件在 `guides/cli.md`，助手技能中的 `references/cli.md` 路径保持稳定。
