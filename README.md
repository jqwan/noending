# NoEnding

> **Conversations end. Context doesn't.**
> 对话会结束，上下文不会。

NoEnding 是一个本地多 Agent 工作空间，基于 Tauri 2、React、TypeScript、Rust 和 SQLite 构建，支持 macOS 与 Windows。
它把分散在不同 Agent 中的会话、项目和任务放到同一个界面，并持续保存工作上下文，让工作能够跨会话、跨 Agent 延续。

## 能做什么

- **管理会话**：统一阅读、搜索不同 Agent 的本地历史，在终端或对应桌面应用中继续。
- **新建会话**：选择项目、工作目录和 Agent，可选跟踪任务，输入消息后启动内嵌终端。
- **组织工作**：项目按 Git 仓库及 worktree、单目录或内置目录组组织；任务关联项目，一个会话可跟踪多个任务。
- **积累上下文**：按需更新或重新生成会话、任务和项目摘要，同时提取用户及项目偏好，支持手动管理和锁定偏好。
- **工作区助手**：在内置项目中使用 Codex、Claude Code 或 Pi，查询工作资料并通过 CLI 管理工作数据。

会话历史和工作数据保存在本机；需要 AI 的操作通过用户自己的 Agent CLI 执行。

## 支持的 Agent

| Agent | 新建会话 | 继续会话 |
| --- | --- | --- |
| Codex | `codex` CLI | CLI 或 Codex 桌面端 |
| Claude Code | `claude` CLI | CLI |
| Pi | `pi` CLI | CLI |
| Antigravity | `agy` CLI | CLI 会话用 CLI；IDE 会话打开应用 |
| Qoder | — | 打开 Qoder 应用 |
| WorkBuddy | — | 桌面端定位到会话 |
| dsh | — | 打开 DeepSeek Harness 应用 |
| ZCode | — | 打开 ZCode 应用 |

以上 Agent 均支持历史摄入。「打开应用」表示只打开桌面应用，不自动定位会话。
新建需要安装对应 CLI，桌面端继续需要安装对应应用。

## 运行工程

需要 Node.js 20、pnpm 9、Rust stable，以及对应平台的 Tauri 2 构建工具。

```bash
git clone https://github.com/jqwan/noending.git
cd noending
pnpm install --frozen-lockfile
pnpm tauri dev
```

生成安装包：

```bash
pnpm tauri build
```

构建产物位于 `src-tauri/target/release/bundle/`。

## 使用

1. 在「Agent」查看安装情况、重新检测 CLI，并管理历史来源目录和手动同步。模型列表可手动刷新，获取后会保留。
2. 在「新会话」选择项目、工作目录和 Agent，在标语下多选该项目的跟踪任务（可选），设置模型与思考等级，再输入消息发送。首次使用 Agent 原生参数，之后沿用该 Agent 上一次成功新建会话的模型设置；项目、目录、Agent 和消息草稿也会记住。Enter 发送，Shift+Enter 换行。
3. 在「会话」阅读、搜索或继续历史会话，通过顶部图标切换历史消息、详情和终端。同一会话可打开多个终端；退出的终端仍可从侧栏进入，已绑定会话的终端可重新连接，也可关闭。
4. 在会话、任务或项目详情中「更新摘要」或「重新生成」。在「设置」配置提取使用的 Agent、模型、思考等级和提示词，并管理用户偏好；项目偏好在项目详情管理。
5. 使用助手时，在「新会话」选择内置的 NoEnding Assistant 项目并发送需求，其会话与其他会话一样显示在侧栏。可在助手目录的 `USER.md` 中补充自己的使用要求。内置 `noending-assistant` 技能统一存放在 NoEnding 的 `skills` 目录，首次准备时为助手项目启用；之后可在技能看板或项目详情中停用，重启或重新打开助手不会自动恢复。
6. 项目、任务和会话可独立归档或取消归档。已归档的项目和任务不能用于新建会话，已归档会话不能继续；项目归档不影响关联任务和会话的归档状态。永久删除需先归档，项目还需没有关联会话，聊天和助手项目不能永久删除。
7. 使用顶部「查找」（macOS `⌘K`、Windows `Ctrl+K`），按名称查找项目、任务、会话或 Agent，并进入对应详情；项目和会话也支持匹配目录。默认展示最近会话与 Agent，已归档对象会明确标记。此入口只查找对象，不匹配消息正文、摘要或任务描述。

永久删除只清理 NoEnding 本地数据，不删除 Agent 源文件；后续同步可能重新摄入仍有源文件的会话。

「技能」看板发现并管理本地 Skill，托管时可迁移源目录到 NoEnding 技能库，或只登记并引用原目录；两种方式均可配置用户级和项目级加载入口。引用的源目录若位于 Agent 生效路径，该物理入口保持启用，迁移后才可直接停用；其他链接入口可正常启停。源目录位于 NoEnding 技能库外的技能可取消托管，并选择是否移除用户级及所有已登记项目中的链接入口；源文件、物理入口和上级目录链接均保留。项目详情页也可配置技能。MCP 由各 Agent 原生方式管理，NoEnding 不扫描或改写其配置。

默认来源和用户添加的来源都直接参与自动同步，无需启用开关。启动、回到前台和手动「增量同步全部」均处理全部已登记来源；逐 Agent、逐来源手动同步保留各自范围。默认来源按 Agent 的会话布局限定扫描范围：Codex 扫描 `sessions` 和 `archived_sessions`，Claude Code、Qoder、WorkBuddy 扫描 `projects`，Dsh 扫描 `sessions`。缺少会话目录时不会退回整个数据目录；用户自定义来源仍扫描指定目录。

历史同步保留来源中的当前有效消息。增量同步跳过未变化的文件，追加时校验已读前缀；检测到改写或截断时重新对账。全量同步强制从头读取，复用未变化的消息 ID，并在完整读取成功后清理已失效的旧消息和搜索索引。来源缺失、读取失败或完整快照解析失败时，保留上次可靠的消息和游标。Codex 的 `.jsonl` 与 `.jsonl.zst` 对应同一会话，同时存在时优先读取 `.jsonl`。

同步不会修改已有 Context；对话被改写后，摘要会标记为待更新，下次显式更新时根据当前消息重新提取。历史界面中的消息编号表示当前对话顺序（ordinal），会随着对话重排或替换而变化。

普通 JSONL 使用流式前缀校验与逐行解析；Codex 普通和压缩来源在单轮同步中复用解析结果。消息正文只保存在消息表中，全文索引通过外部内容视图引用它，搜索文档的定位使用普通数据库索引。未变化的消息、顺序重排及未变化的会话搜索信息不会重复重建全文索引。

消息顺序映射同时保存累计分块位置，CLI 与 Context 分页直接定位所需消息，按页读取正文；启动时不再执行全库搜索文档补齐，正常写入原子维护索引，全量来源同步会逐会话核对消息搜索文档。

会话列表、卡片和侧栏使用独立的轻量列表项，不读取来源元数据、同步游标或摘要正文，也不再截断为 500 条。筛选使用完整列表数据，显示更多时逐步增加渲染条目；终端可用性按可见条目检查，显式开启「可终端继续」筛选时才检查全部候选。Agent 数量单独聚合查询，「查找」只请求少量定位字段；会话摘要只在详情页按需读取。

顶部查找与项目、任务、会话、Agent 看板共用对象匹配规则：项目名称和全部工作目录、任务标题、会话标题/目录/完整 ID、Agent 名称/标识/别名。看板将当前筛选范围的候选 ID 传给数据库，SQL 仅在该范围内匹配全部记录，再按页面规则排序和分批展示；顶部查找只显示结果预览。对象查找不匹配描述、摘要或消息正文。跨会话正文搜索由 CLI `ne search` 使用全文索引；CLI `ne session search` 和 Context 提取 Agent 的 `extraction search` 在各自允许的消息范围内直接匹配正文。历史消息界面使用分页和 ordinal 定位，不调用关键词正文搜索。全文索引仅维护会话信息与当前消息，不再维护项目/任务摘要文档。

当前数据库格式为 **12**，应用启动不自动迁移旧格式数据库。一般格式调整需要显式重建。本次提供独立的格式 11 → 12 一次性离线工具，先备份，仅删除来源的 `enabled` 列，保留现有数据与 ID，见[格式 11 一次性迁移](docs/database-v11-upgrade.md)。

「设置」中可选择浅色、深色或跟随系统，内嵌终端随应用切换配色；Agent 自身的 TUI 主题行为由其控制，Codex CLI 可能需要重新连接才生效。默认存储目录为 macOS 的 `~/.noending/`、Windows 的 `%USERPROFILE%\.noending\`，可在设置中更改，重启后生效。

也可通过 CLI 查询历史、管理偏好和任务、更新摘要。保持应用运行，使用 `ne --help` 查看命令；`ne` 和 `noending` 使用同一套命令。安装及用法见 [CLI 使用说明](docs/cli.md)。

开发约定与验证规则见 [AGENTS.md](AGENTS.md)。
