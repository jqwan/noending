# 任务协作

在用户已开启的任务协作室中，与本次成员完成指定工作。协作室共用一份消息历史，每名成员独立确认阅读位置；信箱仍用于定向联系，不为协作室消息逐人复制信件。

## 协作模式与持续参与

进入协作意味着在当前模型轮次中持续参与，交流在协作室完成：

1. **只在房间沟通**：本次工作交流使用协作室，不将同一正文复制到信箱或宿主界面。
2. **严禁因空闲交卷**：暂无任务、发言完毕、wait 返回 timeout，都不代表协作结束，**不得因空闲或超时提交宿主最终回复**。
3. **标准闭环**：`join` → `wait` → 逐条完整查阅 → 按需回复或执行 → `ack` 已实际查阅部分 → 继续工作或 `wait`。
4. **等待同一进程**：区分「CLI 等待超时（--timeout 到期）」与「宿主工具单次同步等待上限（工具先返回进程仍在运行）」：若宿主工具先返回运行中，继续等同一进程，不能误作 CLI 结束重起监听，更不能留下后台进程就结束模型轮次；单次 timeout 仅结束一次等待，应再次 wait。
5. **持续参与原则**：用户没有明确停止就一直保持监听，不按空闲时长或 timeout 次数自动退场。真实宿主时长、额度或连接硬限制使继续不可行时，如实说明原因与未交付工作，尽可能 leave 后再结束。
6. **退场顺序**：若运行仍有效且需退出，先 `ack` 已实际阅读的部分，再调用 `leave`，不要求追到持续增长的最新位置；收到 `stopped` 后直接 `leave` 收尾，无需追读或补 ack 全部历史。

## 加入与职责

先按[接入规则](access.md)核对 Home，按[身份发现](identity.md)取得自己的 NoEnding 会话 ID。用加入邀请中的任务、房间和运行 ID 查询当前运行、成员及负责人，确认自己在本次成员中后再加入。打开应用或终端不等于加入，任务关联也不等于已获本次协作授权。旧运行已停止时，不用旧 run 发信，也不自行开启新一轮。

读取任务标题、描述及与自身分工相关的任务事项，核对当前目标和验收边界。负责人负责协调分工、整合交付、按[任务管理](task.md)维护描述中的目标、现状与事项进展；普通成员按分工执行，将必要的成果、证据和阻碍报告给负责人。无负责人时由用户协调，不自行宣布拥有停止权限。用户明确要求成员维护某项记录时，按其要求操作。

分工消息说清预期成果、责任边界和交接条件；涉及同一代码库时约定工作树或文件归属，保留他人修改。分配工作不扩大用户授权，也不把协作成员自动视为全部相关会话。任务归属和进展维护遵循[任务管理](task.md)，不为每轮讨论追加任务流水账。

## 查阅、执行与等待方式

按消息 seq 顺序分页查阅当前 run 的未读内容。读取和发送均不自动确认阅读位置；只有确已读过的一段消息才显式 ack 到该段最后的 seq，不能越过未查阅的他人或用户消息。未读计数不包含自己的发言，但 wait 的序列批次可能伴随返回自己的消息；不要求序号在数值上连续。

**ack 语义**：ack 只表示已经查阅，不表示同意、接手、答复或对应任务完成。需要承诺或回答的问题不能用沉默或 ack 代替。不按未读数量、时间戳或页面条数推算阅读位置。

有明确工作时先推进，在影响分工的变更、阻碍、交付及其他安全检查点查看新消息；空闲或等待依赖时保持等待。按当前宿主暴露的工具能力选择等待方式，以减少无效模型往返：

1. **支持较长同步执行**：直接执行 `room wait`，省略 `--timeout` 或按宿主允许上限设置，不要故意传很短的超时。
2. **返回运行中任务/进程 ID**：继续等待同一任务；有本轮内完成通知时可使用，不能留下后台脚本后提交宿主最终回复。
3. **只能分段等待**：使用允许的较长等待；超时后按实际进程存活情况续等或重试，不重复启动多个监听。

空等期间不输出心跳文字，不重复查询 `room show` 或完整历史。可将上一批已读的 ack 与下一次 wait 合并为一次工具调用执行，但不能在模型尚未阅读返回材料前自动 ack。出现 `next_cursor` 时保持参数分页续读，不以减少 limit 截断历史。连接有效只证明参与通道存活，不能证明模型必然在轮内响应；缺乏必要等待工具时如实报告限制。

## 发言与收尾

### 应发言

- 明确要求自己答复、接手或给出判断，完成沟通闭环。
- 提供可验收交付、关键阶段成果或测试证据。
- 遇到需要对方行动、变更计划或调整分工的真实阻碍。
- 新事实、反例或关键纠错会影响当前决定。

请求应说清回应对象和所需行动。先写结论或请求，引用必要的任务事项、提交、文件、测试证据或房间 seq；通常一小段、尽量 300 字符内，不做硬截断。长证据留在可访问的材料中，不重复贴整屏日志或任务进展。

### 不发言

- 只表示已读、收到：推进 ack 阅读位置即可。
- 纯同意、附和、复述已有结论，没有新增信息。
- 无行动要求的通知，且不影响自身分工。
- 已有意见已被负责人归并，自己没有新事实或实质反例。

讨论中负责人提出明确问题，成员尽量一次给出完整意见，由负责人归并共识与分歧；归并后成员不循环确认。

### 停止与收尾

负责人核实整体完成及验证缺口后可停止当前协作；普通成员交付本职成果后继续监听或按约退出，不能代替负责人停止。收到 `stopped` 或确认已停止后，不再 wait、接新工作或向已停止的运行发信。

停止协作不强制结束正在执行的编译或测试，也不强行关闭终端；在下一安全检查点查询状态并收尾。调用 `leave` 清理本人参与，已经退出或参与已删除时结束收尾。若停止时仍有尚未交付的关键成果或阻碍，通过原本已获授权的定向渠道向负责人简要交接，附 task/run 及成果位置。停止协作后保留任务和事项记录。

## 操作参考

`ne` 使用接入规则确认的入口，SELF 是自己的 NoEnding 会话 ID。CLI/MCP 参与和写入都显式提供自身身份，内嵌终端以实际绑定为准；外部 `from_session` 是申报身份而非认证，阅读位置仅是以该身份写入的查阅声明。

| 目的 | CLI | MCP |
| --- | --- | --- |
| 按任务定位 | `ne room resolve --task TASK` | `room_resolve {task:TASK}` |
| 核对运行和成员 | `ne room show ROOM` | `room_show {room:ROOM}` |
| 加入本次运行 | `ne room join ROOM --run RUN --from-session SELF` | `room_join {room:ROOM,run:RUN,from_session:SELF}` |
| 等待未读 | `ne room wait ROOM --run RUN --from-session SELF [--timeout SECONDS]` | `room_wait {room:ROOM,run:RUN,from_session:SELF,timeout_seconds?}` |
| 查询历史或续页 | `ne room messages ROOM [--run RUN] [--cursor CURSOR]` | `room_messages {room:ROOM,run:RUN,cursor?}` |
| 确认查阅位置 | `ne room ack ROOM --run RUN --from-session SELF --through-seq N` | `room_ack {room:ROOM,run:RUN,from_session:SELF,through_seq:N}` |
| 简要发言 | `ne room send ROOM --run RUN --from-session SELF --message TEXT` | `room_send {room:ROOM,run:RUN,from_session:SELF,message:TEXT}` |
| 退出本人参与 | `ne room leave ROOM --run RUN --from-session SELF` | `room_leave {room:ROOM,run:RUN,from_session:SELF}` |
| 负责人停止 | `ne room stop ROOM --run RUN --from-session SELF` | `room_stop {room:ROOM,run:RUN,from_session:SELF}` |

`join` 与 `wait` 回包附带 `notice` 操作提示（如 timeout 提示继续 wait，stopped 提示 leave 收尾）。
`ack` 回执返回事务内实际生效的位置（若请求值小于已持久化位置，回执为已有的最大生效位置，保证只进不退）。
`send` 要求发件成员在当前运行中且尚未 leave（用户入口不受此限）；正文不能为空。
wait 的 `status=messages` 时处理消息；`timeout` 仅表示本次等待到期，应继续等待；`stopped` 直接进入收尾。返回下一页游标时，保持 room/run，原样回传 messages 续读，按 seq 完整处理后再 ack。历史首屏返回最近一页，其 next_cursor 指向更旧页；wait 的 next_cursor 指向本批后续消息，不能改变其范围或自行构造游标。

需要长材料时用可访问的文件或任务事项引用；确需发正文可用 `--file UTF8_FILE` 代替 `--message`。写入可携带 `--request-id` / `request_id`，超时先查回执，原操作重试沿用相同 request_id 与参数，不能把无回复当作发送失败。接口返回 run 已停止、身份不符或参与关系失效时，重新查询状态，不能通过换 run、冒用成员或重复 join 绕过。CLI/MCP 不提供成员配置或任意开启协作的入口，用户先从任务页面开启本次协作。

退出时调用 leave 清理本人此次参与；已经退出、参与目标已删除时结束收尾，不重建参与或循环重试。旧 run 的清理不能影响新 run。

## 协作摘要

需要接手或恢复讨论时，可先用 `ne task summary TASK_ID` 读取当前协作摘要，再按个人阅读位置查阅未读消息及必要原文，不以摘要覆盖位置跳过未读消息。协作摘要每任务一份，跨多次协作运行延续；`processed_through_seq` 是已纳入摘要的房间消息位置，`pending_messages` 是尚待整理的协作消息数，与个人已读位置互相独立。

需要整理时按[摘要提取](extraction.md)使用 kind=task。用户或已获授权的协调者按需触发，不每条消息都提取、不在停止协作时强制等待。摘要保留重要共识、原因、依赖、交接与未解决分歧；具体执行仍维护任务事项。没有协作记录时无需生成，摘要不可用不妨碍继续工作。
