摘要按事项组织为 items 数组，每个事项包含 title（标题）、description（一句话简短结论或说明）、details（具体细则字符串数组）。一个事项围绕一个可独立理解、检索和更新的问题组织；同一问题的决定、原因、成果和边界放在一起，不同的独立问题不要为了减少数量塞进同一事项。不强制目标、进展、待办等固定栏目，不凑条数；简单事项可以很短，description 可为空字符串，details 可为空数组。
标题建议不超过 20 字符，描述建议不超过 60 字符，每条细则建议不超过 80 字符，整个事项的标题、描述和细则合计建议不超过 300 字符（均含空格与标点）。这些长度是精简目标，不是凑字要求，不直接截断；必要的路径、命令或准确解释可以适当超出。标题是非空单行文字；描述和细则仅用必要的行内 Markdown 表达路径、命令或强调，不写 Markdown 标题或嵌套列表，细则本身不加列表前缀。
事项数量由重要、独立的内容决定，按对应摘要类型的项数上限整理；锁定标题必须保留，不为满足项数目标而删除，必要时减少其他事项。未锁定的标题、描述、细则可修改、融合、简化、增加或删除，事项可合并、拆分、删除和重新排序。locked_titles 列出的标题必须原样保留，不能通过改名、删除或合并使其消失；描述和细则仍可根据材料更新、融入相关信息，事项可以重新排序。已有事项不是固定槽位，每次更新都应重新检查相关性和有效性，不仅追加新事项。
接近项数上限时，先合并真正围绕同一问题的事项，清理重复、失效或已被取代的信息，再精简次要内容。不要合并无关问题，不为新增事项挤掉仍重要的早期结论，也不按日期、批次或更新记录扩张列表。若整理后仍超过上限，保留对整体理解和后续使用最重要的独立事项，舍弃次要事项。整体篇幅随必要事项浮动，不为压缩整份摘要而将独立事项混在一起。现有事项的 id 是稳定引用，改名、更新内容或重排时保留；合并只沿用一个被合并事项的 id，拆分只有一个延续事项保留 id。新增事项省略 id，由程序生成，不编造 ID。重新生成时也依据 item_identities 核对延续事项。
只按结果协议写出完整结构化摘要，不输出完整 Markdown 正文、包裹 JSON 的代码围栏或更新补丁。例如：
